The Vendors API lets external systems read and update individual vendor records. The public API does **not** create vendors or services — vendor creation happens through the dashboard or the [Import API](/import-api).

All endpoints are org-scoped to the API key making the request. See [API conventions](/conventions) for authentication, ID formats, timestamps, and the error envelope.

## Retrieve a vendor

<ParamField path="method" type="GET">
  `GET /v1/vendors/{vendor_id}`
</ParamField>

Returns a single vendor.

### Path parameters

<ParamField path="vendor_id" type="string" required>
  The Coverbase vendor ID (`cbvndr_...`).
</ParamField>

### Example request

```bash cURL
curl -X GET "https://api.coverbase.app/v1/vendors/cbvndr_e448ba62882143f3ba0c140bb2e30162" \
  -H "Authorization: Bearer ak_live_xxx"
```

### Response fields

<ResponseField name="id" type="string">
  The Coverbase vendor ID (`cbvndr_...`).
</ResponseField>

<ResponseField name="external_id" type="string | null">
  External system identifier, if one was set when the vendor was imported.
</ResponseField>

<ResponseField name="name" type="string">
  Vendor name.
</ResponseField>

<ResponseField name="website" type="string | null">
  Vendor website URL.
</ResponseField>

<ResponseField name="description" type="string | null">
  Vendor description.
</ResponseField>

<ResponseField name="hq_location" type="string | null">
  Headquarters location.
</ResponseField>

<ResponseField name="status" type="string | null">
  The vendor's current status as a plain label string (e.g. `"Active"`). Statuses are org-customizable. `null` if the vendor has no status set.
</ResponseField>

<ResponseField name="status_id" type="string | null">
  The ID (`cbst_...`) of the vendor's current status record.
</ResponseField>

<ResponseField name="tags" type="string[]">
  Array of tag value strings. Empty array if the vendor has no tags.
</ResponseField>

<ResponseField name="risk_analyst_ids" type="string[]">
  User IDs (`cbuser_...`) of assigned risk analysts.
</ResponseField>

<ResponseField name="relationship_owner_ids" type="string[]">
  User IDs (`cbuser_...`) of relationship owners.
</ResponseField>

<ResponseField name="inherent_risk_level_id" type="string | null">
  Scale level ID (`cbsclvl_...`) representing inherent risk.
</ResponseField>

<ResponseField name="residual_risk_level_id" type="string | null">
  Scale level ID (`cbsclvl_...`) representing residual risk.
</ResponseField>

<ResponseField name="engagement_type" type="string | null">
  Type of engagement with this vendor.
</ResponseField>

<ResponseField name="use_case" type="string | null">
  How the vendor is used within the organization.
</ResponseField>

<ResponseField name="created_at" type="integer">
  Unix timestamp (seconds) when the vendor record was created.
</ResponseField>

<ResponseField name="updated_at" type="integer">
  Unix timestamp (seconds) of the last update.
</ResponseField>

### Error responses

| Status | Body | When |
| ------ | ---- | ---- |
| 404 | `{"detail": {"code": "vendor_not_found", "message": "Vendor not found."}}` | The `vendor_id` does not exist or is not in the API key's org. |

## Update a vendor

<ParamField path="method" type="PATCH">
  `PATCH /v1/vendors/{vendor_id}`
</ParamField>

Updates one or more fields on an existing vendor. Only the fields you include are changed; omitted fields are left untouched. The response is the full, refreshed vendor object (same shape as the GET response above).

<Note>
  Every field in the update body is optional and nullable in the request schema. There is no separate "clear to null" behavior — sending `null` for a field is treated the same as omitting it (the field is not changed).
</Note>

### Request body

<ParamField body="name" type="string">
  Vendor name.
</ParamField>

<ParamField body="website" type="string">
  Vendor website URL.
</ParamField>

<ParamField body="description" type="string">
  Vendor description.
</ParamField>

<ParamField body="hq_location" type="string">
  Headquarters location.
</ParamField>

<ParamField body="status_id" type="string">
  ID (`cbst_...`) of a status record to transition the vendor to.
</ParamField>

<ParamField body="tag_ids" type="string[]">
  Replace the entire tag set, using tag IDs (`cbtag_...`).
</ParamField>

<ParamField body="risk_analyst_ids" type="string[]">
  Replace the entire set of risk analyst user IDs (`cbuser_...`).
</ParamField>

<ParamField body="relationship_owner_ids" type="string[]">
  Replace the entire set of relationship owner user IDs (`cbuser_...`).
</ParamField>

<ParamField body="inherent_risk_level_id" type="string">
  Scale level ID (`cbsclvl_...`) for inherent risk.
</ParamField>

<ParamField body="residual_risk_level_id" type="string">
  Scale level ID (`cbsclvl_...`) for residual risk.
</ParamField>

<ParamField body="use_case" type="string">
  How the vendor is used within the organization.
</ParamField>

<ParamField body="engagement_type" type="string">
  Type of engagement with this vendor.
</ParamField>

### Example request

<CodeGroup>

```bash cURL
curl -X PATCH "https://api.coverbase.app/v1/vendors/cbvndr_e448ba62882143f3ba0c140bb2e30162" \
  -H "Authorization: Bearer ak_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "status_id": "cbst_offboarding7f8e9d0c1b2a3f4e5d6c7b8a9f0e1d2c",
    "use_case": "Legacy system — winding down"
  }'
```

```python Python
import os
import requests

API_KEY = os.environ["COVERBASE_API_KEY"]
BASE_URL = "https://api.coverbase.app"

vendor_id = "cbvndr_e448ba62882143f3ba0c140bb2e30162"
payload = {
    "status_id": "cbst_offboarding7f8e9d0c1b2a3f4e5d6c7b8a9f0e1d2c",
    "use_case": "Legacy system — winding down",
}

resp = requests.patch(
    f"{BASE_URL}/v1/vendors/{vendor_id}",
    headers={
        "Authorization": f"Bearer {API_KEY}",
        "Content-Type": "application/json",
    },
    json=payload,
    timeout=30,
)
resp.raise_for_status()
print(resp.json())
```

</CodeGroup>

### Error responses

| Status | Body | When |
| ------ | ---- | ---- |
| 400 | `{"detail": {"code": "invalid_update", "message": "..."}}` | The update was rejected (e.g. an invalid `status_id` or other reference ID). `message` contains the reason. |
| 404 | `{"detail": {"code": "vendor_not_found", "message": "Vendor not found."}}` | The `vendor_id` does not exist or is not in the API key's org. |
| 422 | Standard validation error | The request body failed schema validation. See [API conventions](/conventions#validation-errors). |
