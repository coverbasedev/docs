The Vendors API lets external systems read and update individual vendor records. To create or bulk-update vendors, use the [Import API](/import-api) instead.

The most common use of this API is lifecycle transitions: signaling that a vendor is offboarding, suspending a vendor pending review, or unblocking a procurement record once an assessment completes.

## Retrieve a vendor

<ParamField path="method" type="GET">
  `GET /v1/vendors/{vendor_id}`
</ParamField>

Returns the full profile of a single vendor.

### Path parameters

<ParamField path="vendor_id" type="string" required>
  The Coverbase vendor ID (`cbvndr_...`).
</ParamField>

### Example request

```bash cURL
curl -X GET "https://api.coverbase.app/v1/vendors/cbvndr_e448ba62882143f3ba0c140bb2e30162" \
  -H "Authorization: Bearer <api-key>"
```

## Update a vendor

<ParamField path="method" type="PATCH">
  `PATCH /v1/vendors/{vendor_id}`
</ParamField>

Updates one or more fields on an existing vendor. Most commonly used to transition lifecycle state. Updates fire `vendor.updated` and, if status changes, `vendor.status_changed` webhooks.

### Updatable fields

<ParamField body="status_id" type="string">
  ID of a `CbStatus` record to transition to. Must be a valid, non-archived vendor status for the org.
</ParamField>

<ParamField body="name" type="string">
  Vendor name.
</ParamField>

<ParamField body="website" type="string or null">
  Vendor website URL. Send an empty string to clear.
</ParamField>

<ParamField body="description" type="string or null">
  Vendor description.
</ParamField>

<ParamField body="hq_location" type="string or null">
  Headquarters location.
</ParamField>

<ParamField body="risk_analyst_ids" type="array">
  Replace the entire set of risk analyst user IDs.
</ParamField>

<ParamField body="relationship_owner_ids" type="array">
  Replace the entire set of relationship owner user IDs.
</ParamField>

<ParamField body="tag_ids" type="array">
  Replace the entire tag set using `CbTag` IDs.
</ParamField>

<ParamField body="inherent_risk_level_id" type="string or null">
  Scale level ID for inherent risk.
</ParamField>

<ParamField body="residual_risk_level_id" type="string or null">
  Scale level ID for residual risk.
</ParamField>

<ParamField body="raw_irq_score" type="float or null">
  Raw IRQ score value.
</ParamField>

<ParamField body="next_assessment_date" type="integer or null">
  Unix timestamp of the next scheduled assessment.
</ParamField>

<ParamField body="use_case" type="string or null">
  How the vendor is used within the organization.
</ParamField>

<ParamField body="engagement_type" type="string or null">
  Type of engagement with this vendor.
</ParamField>

<ParamField body="custom_field_data" type="array">
  Array of custom field value objects for org-specific fields.
</ParamField>

### Example request

<CodeGroup>

```bash cURL
curl -X PATCH "https://api.coverbase.app/v1/vendors/cbvndr_e448ba62882143f3ba0c140bb2e30162" \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "status_id": "cbsts_offboarding_7f8e9d0c",
    "use_case": "Legacy system — winding down"
  }'
```

```python Python
import os
import requests

API_KEY = os.getenv("COVERBASE_API_KEY")
BASE_URL = "https://api.coverbase.app"

headers = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json",
}

vendor_id = "cbvndr_e448ba62882143f3ba0c140bb2e30162"
payload = {
    "status_id": "cbsts_offboarding_7f8e9d0c",
    "use_case": "Legacy system — winding down",
}

resp = requests.patch(
    f"{BASE_URL}/v1/vendors/{vendor_id}",
    headers=headers,
    json=payload,
    timeout=30,
)
resp.raise_for_status()
print(resp.json())
```

</CodeGroup>

<Info>
  This update fires both `vendor.updated` and `vendor.status_changed` webhooks. Any workflow bound to those events will run, for example the offboarding sequence described in [Workflow C: Vendor offboarding](/integrations/end-to-end-workflows#workflow-c-vendor-offboarding).
</Info>

## Vendor statuses

Vendor statuses are org-customizable. Each status belongs to a group (`unstarted`, `started`, `completed`, `canceled`). Use the dashboard or a list statuses endpoint to see available statuses for your org.

Any valid, non-archived vendor status ID can be set via `status_id`. Status transitions are not enforced — you can move a vendor to any status that exists for your org.

<Info>
  Statuses are `CbStatus` records with `target_type=VENDOR`. Each org defines their own status labels, colors, and groups. If you need to discover available statuses programmatically, query the statuses list endpoint filtered by target type.
</Info>

## Error responses

| Status | Code | When |
| ------ | ---- | ---- |
| 400 | `invalid_status_id` | The provided `status_id` doesn't exist, is archived, or isn't a vendor status for this org. |
| 400 | `missing_required_field` | A required field was omitted. |
| 404 | `vendor_not_found` | The provided `vendor_id` does not exist or is not accessible to the API key. |
