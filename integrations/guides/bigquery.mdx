A BigQuery destination is part of [warehouse data share](/products/warehouse-data-share). Coverbase writes through the BigQuery REST API with a service account key, creates one table per contract table on the first sync, and keeps a `<table>_current` view beside each.

## Prepare BigQuery

1. Create a service account for Coverbase.
2. Grant it **BigQuery Data Editor** on the dataset and **BigQuery Job User** on the project.
3. Create a JSON key for the service account.

The dataset is created if it does not exist yet, in the location you give.

## Add the destination in Coverbase

1. Open **Configuration → Data Share** and click **Add destination**.
2. Choose **BigQuery**, give it a **Name**, and choose **Hourly** or **Daily**.
3. Enter the **Project ID**, **Dataset** and **Location**, and paste the **Service Account Key (JSON)**.
4. Click **Add destination**, then **Test connection**, then **Sync now**.

After saving, the card shows the service account's email as a hint. The key is never shown again. Archiving the destination deletes it.

## What lands in BigQuery

- One table per contract table, created on the first sync, with any column the contract adds later added to it.
- Each sync appends the rows that changed, stamped with `_cb_synced_at`.
- A `<table>_current` view per table keeps the newest version of each row.

Point Looker Studio, Power BI or Tableau at the `_current` views.
