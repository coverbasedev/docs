Each feature has its own gate. When your organization does not have the feature, its endpoints return `404` with one of these codes:

| Code | Feature |
| ---- | ------- |
| `inspect_not_enabled` | Inspect |
| `dark_web_not_enabled` | Dark web monitoring |
| `certificates_not_enabled` | Certificate Vault |

When your organization enforces roles and the key lacks the permission, the endpoint returns `403`.

Some actions stay with a signed-in person. When an API key calls one of them, the endpoint returns `403` with the code `api_key_not_allowed`. These actions are: archiving or restoring a document insight, deleting an insight group or target, stopping an Inspect schedule, removing a watchlist identifier, marking a certificate `verified`, archiving a certificate, archiving a rule set, deleting an insight example or value, and archiving or restoring an org document.

## Pause or resume an Inspect schedule

<ParamField path="method" type="POST">
  `POST /v1/inspect-schedules/{schedule_id}/pause`
</ParamField>

<ParamField path="method" type="POST">
  `POST /v1/inspect-schedules/{schedule_id}/resume`
</ParamField>

To stop a schedule from starting inspections for a while, pause it. To start it again, resume it. Both return the updated schedule in the same shape as the list items. Pausing a paused schedule changes nothing.

<ParamField path="schedule_id" type="string" required>
  The schedule ID.
</ParamField>

### Errors

| Status | Code | Meaning |
| ------ | ---- | ------- |
| `404` | `schedule_not_found` | No schedule with this ID in your organization. |
| `409` | `schedule_archived` | The schedule was stopped. Create a new one in Coverbase instead. |

## Create an Inspect schedule

<ParamField path="method" type="POST">
  `POST /v1/inspect-schedules`
</ParamField>

Returns `201` with the new schedule. A drift schedule repeats every `interval_seconds`; every other purpose runs monthly on `day_of_month`.

<ParamField body="target_id" type="string" required>
  The Inspect application to inspect.
</ParamField>

<ParamField body="control_set_ids" type="string[]" required>
  Control sets each inspection checks, in order.
</ParamField>

<ParamField body="day_of_month" type="integer">
  Day of the month to run, for evaluative and exploratory schedules.
</ParamField>

<ParamField body="interval_seconds" type="integer">
  Seconds between runs, for drift schedules.
</ParamField>

<ParamField body="purpose" type="string" default="evaluative">
  `evaluative`, `exploratory`, or `drift`.
</ParamField>

<ParamField body="browser_evidence_allowed" type="boolean" default="true">
  Whether inspections may collect browser evidence.
</ParamField>

An unknown application returns `422` with `target_not_found`, an archived one `target_archived`, and an invalid cadence or control set `schedule_invalid`.

To change a schedule's cadence or control sets, send `PATCH /v1/inspect-schedules/{schedule_id}` with any of `day_of_month`, `interval_seconds`, and `control_set_ids`. To stop it for good, send `DELETE /v1/inspect-schedules/{schedule_id}`.

## Create and manage document insights

To create an insight, send `POST /v1/document-insights`. It returns `201` with the insight.

<ParamField body="field_name" type="string" required>
  The insight's name, for example "Governing law".
</ParamField>

<ParamField body="field_key" type="string">
  A stable key. Defaults to `field_name`. A key already in use returns `409` with `field_key_exists`.
</ParamField>

<ParamField body="field_description" type="string">
  What to extract and how.
</ParamField>

<ParamField body="field_type" type="string" default="string">
  `string`, `number`, `date`, or `boolean`.
</ParamField>

<ParamField body="field_mode" type="string" default="extraction">
  `extraction` quotes the document; `synthesis` writes text from it.
</ParamField>

<ParamField body="document_types" type="string[]">
  Document types the insight reads. Empty means all.
</ParamField>

<ParamField body="group_id" type="string">
  The insight group to file it under.
</ParamField>

<ParamField body="update_policy" type="string" default="auto_fill">
  `auto_fill`, or `review_required` to hold each change for a reviewer.
</ParamField>

<ParamField body="reviewer_user_id" type="string">
  The reviewer for `review_required` changes.
</ParamField>

To retire an insight and keep its values, send `POST /v1/document-insights/{config_id}/archive`. To bring it back, send `POST /v1/document-insights/{config_id}/restore`.

### Targets

A target links an insight to a built-in contract or document field it fills. To list them, send `GET /v1/document-insights/{config_id}/targets`. To add one, send `POST /v1/document-insights/{config_id}/targets` with `object_type` (`contract` or `vendor_document`), `field_name`, and optionally `conflict_policy` (`fill_if_empty`, `latest_document_wins`, `never_overwrite`), `min_confidence` (`low`, `medium`, `high`), `require_grounded`, and `enabled`. A pairing no parser covers returns `422` with `target_not_supported`; a field the insight already fills returns `409` with `target_exists`.

To change a target, send `PATCH /v1/document-insight-targets/{target_id}`. To stop filling the field, send `DELETE /v1/document-insight-targets/{target_id}`. Values already written stay.

### Groups

To list groups, send `GET /v1/document-insight-groups`. To create one, send `POST /v1/document-insight-groups` with `name` and optionally `description`, `document_types`, `sort_order`, and `enabled`. To change one, send `PATCH /v1/document-insight-groups/{group_id}`; changing `document_types` rescopes every insight that inherits from the group. To delete one, send `DELETE /v1/document-insight-groups/{group_id}`. Its insights stay, outside any group.

## Manage dark web monitoring

To read the policy, send `GET /v1/dark-web/config`. To change it, send `PATCH /v1/dark-web/config` with any of `is_enabled`, `monitor_organization`, `vendor_scope` (`radar_monitored` or `all`), `enabled_sources`, `lookalikes_for_vendors`, `confidence_threshold` (0 to 1), and `business_hours`. Coverbase re-derives the watchlist right away, and switching monitoring on creates the dark web roles.

### Review an exposure

To record a triage decision, send `PATCH /v1/dark-web/exposures/{exposure_id}/review`. Only the fields you send change.

<ParamField body="review_status" type="string">
  The new review status. Coverbase records every step in between.
</ParamField>

<ParamField body="review_note" type="string">
  A note on the decision. Send `null` to clear it.
</ParamField>

<ParamField body="false_positive_reason" type="string">
  Required with `false_positive`.
</ParamField>

<ParamField body="assigned_user_id" type="string">
  Assign the exposure to this member. They are notified.
</ParamField>

<ParamField body="clear_assignee" type="boolean" default="false">
  Remove the current assignee.
</ParamField>

Moving to `new`, `confirmed`, or `with_legal` runs your alert rules. Errors: `404` `exposure_not_found`, `422` `assignee_not_member`, `422` `review_not_allowed`.

### Watchlist

To list watched identifiers, send `GET /v1/dark-web/watchlist`. Values are masked. To add one, send `POST /v1/dark-web/watchlist` with `subject_kind` (`organization` or `vendor`), `asset_type`, `value`, and `vendor_id` for a vendor identifier. Optional fields: `label`, `role` (domains), `program_vendor_id`, `card_kind`, `card_network` (BINs), and `linked_asset_id` (mailboxes). Adding an identifier already there re-enables it.

To turn one on or off or change its details, send `PATCH /v1/dark-web/watchlist/{asset_id}`. To stop watching it, send `DELETE /v1/dark-web/watchlist/{asset_id}`; a derived identifier is switched off instead of removed.

### Playbooks

To list every response checklist, send `GET /v1/dark-web/playbooks`. To replace one with your own steps, send `PUT /v1/dark-web/playbooks/{key}` with `steps`, a list of `{ "id": optional, "label": required }`. To go back to Coverbase's default, send `DELETE /v1/dark-web/playbooks/{key}`.

## Manage certificates and prequalification

To record a certificate by hand, send `POST /v1/vendor-certificates` with `vendor_id`, `certificate_type`, `name`, and optionally `issuer`, `scope`, `result`, `coverages`, `valid_from`, `valid_to`, and `vendor_document_id`. Coverbase re-checks the vendor's prequalification.

To record a person's check, send `PATCH /v1/vendor-certificates/{certificate_id}/verification` with `verification_status` (`unverified`, `verified`, `discrepancy`) and `verification_note`. To archive a certificate, send `DELETE /v1/vendor-certificates/{certificate_id}`.

To ask a vendor for a certificate, send `POST /v1/vendor-certificate-requests` with `vendor_id`, `certificate_type`, `message`, and `due_at`. The response gives the unsent supplier portal's `portal_id`.

To ask for renewals in bulk, send `POST /v1/certificate-renewal-jobs` with `certificate_ids`, `message`, and `due_at`. It returns `202` with the job. To follow it, poll `GET /v1/certificate-renewal-jobs/{job_id}` until `status` is final; the counts show how many requests were sent, skipped, or failed.

To pull certificates from a connected network now, send `POST /v1/certificate-networks/{network}/sync` with `isnetworld`, `avetta`, or `ecovadis`. It returns `202`.

### Rule sets

A rule set lists the certificates vendors must hold. To list them, send `GET /v1/prequalification-rule-sets`. To create or replace one, send `POST /v1/prequalification-rule-sets` or `PUT /v1/prequalification-rule-sets/{rule_set_id}` with `name`, `description`, `applies_to`, `rules`, `expiry_reminder_days`, and `blocks_on_failure`. Coverbase re-checks every governed vendor in the background. To archive one, send `DELETE /v1/prequalification-rule-sets/{rule_set_id}`.

To see where a vendor stands, send `GET /v1/vendors/{vendor_id}/prequalification`. To re-check it now, send `POST /v1/vendors/{vendor_id}/prequalification/refresh`.

## Get a vendor's security benchmark

<ParamField path="method" type="GET">
  `GET /v1/vendors/{vendor_id}/security-benchmark`
</ParamField>

Returns where the vendor's outside-in security score sits among your other rated vendors: `score`, `rated_vendors`, `percentile` (null until enough vendors are rated), and `grade_counts`.

## Query the Certificate Vault

<ParamField path="method" type="POST">
  `POST /v1/vendor-certificates/query`
</ParamField>

Returns certificates that match a unified filter, in the same shape as the list endpoint.

<ParamField body="vendor_id" type="string">
  Only this vendor's certificates.
</ParamField>

<ParamField body="search" type="string">
  Text match on the certificate or vendor name.
</ParamField>

<ParamField body="filter" type="object">
  A unified filter rule group, the same DSL the other `/query` endpoints take.
</ParamField>

<ParamField body="sort_by" type="string">
  One of `vendor_name`, `name`, `certificate_type`, `source`, `valid_to`, `created_at`.
</ParamField>

<ParamField body="sort_desc" type="boolean" default="false">
  Sort descending.
</ParamField>

<ParamField body="limit" type="integer" default="50">
  Page size, from 1 to 500.
</ParamField>

<ParamField body="offset" type="integer" default="0">
  Number of certificates to skip.
</ParamField>

To see which certificate networks you connected, send `GET /v1/certificate-networks`. Each item has `network`, `display_name`, `is_connected`, `certificate_count`, and `last_synced_at`. Credentials are never returned.

## Correct a vendor's external security scan

These endpoints change what the outside-in scan sees. The scan target belongs to the company, so every org linked to it sees the correction. Each write that changes the scan starts a rescan; `rescan_started` false means the rescan is queued, not dropped.

- To point the scan at the right domain, send `POST /v1/vendors/{vendor_id}/external-security/rescan` with `domain`. The response gives the host it reduced to.
- To record whether an attributed asset is the vendor's, send `POST /v1/vendors/{vendor_id}/external-security/estate-reviews` with `kind` (`domain` or `host`), `identifier`, `review` (`unreviewed`, `confirmed`, `disputed`), and an optional `note`. Only a change into or out of `disputed` starts a rescan.
- To add hosts or addresses the scan missed, send `POST /v1/vendors/{vendor_id}/external-security/estate-assets` with `identifiers` and an optional `note`. The response lists `added`, `already_present`, and `rejected`.
- To see the companies the rating is compared against, send `GET /v1/vendors/{vendor_id}/external-security/peers`. To queue the work a stale comparison needs, send `POST /v1/vendors/{vendor_id}/external-security/peers/refresh`. Set `force` to re-choose the peers.

Errors use the codes `not_found`, `forbidden`, and `invalid`.

## List continuous monitoring findings

To list findings about your vendors, send `GET /v1/vendor-scan-results` with optional `vendor_id`, `risk_category`, `severity_low`, `severity_high`, `limit`, and `offset`. To get one, send `GET /v1/vendor-scan-results/{scan_result_id}`. Each item has `title`, `summary`, `risk_category`, `severity`, `urls`, and `published_at`.

## Review an extracted insight value

To accept an extracted value as the answer, send `POST /v1/document-insight-values/{data_id}/accept` with the value you saw in `value_string`, `value_number`, `value_date`, or `value_boolean`. A value that changed since returns `409` with `value_changed`. Accepting does not claim the quote was verified.

To mark a value correct or incorrect, send `POST /v1/document-insight-values/{data_id}/verdict` with `verdict` (`correct`, `incorrect`, or null to clear).

## Teach a document insight with examples

A worked example shows an insight an excerpt and the answer it should give. An enabled example is part of what extraction is asked, so each change starts a new revision of the insight.

- To list examples, send `GET /v1/document-insights/{config_id}/examples`.
- To add one, send `POST /v1/document-insights/{config_id}/examples` with `document_excerpt`, `expected_value` (the answer in the insight's type, or null for "not in the document"), and optionally `explanation`, `document_id`, and `enabled`. An answer that does not fit the insight's type returns `422` with `invalid_expected_value`.
- To change one, send `PATCH /v1/document-insight-examples/{example_id}`. Only the fields you send change.
- To delete one, send `DELETE /v1/document-insight-examples/{example_id}`.
- To build an example from an extracted value, send `POST /v1/document-insight-values/{data_id}/to-example` with an optional `explanation`. A value that cites no document text returns `422` with `no_cited_text`.

## Re-run insights over existing documents

A backfill re-extracts insights in the background and costs model calls. Manual values are never overwritten.

To see what a backfill would do, send `POST /v1/document-insight-backfills/preview`. It runs nothing.

<ParamField body="mode" type="string" default="never_attempted">
  `never_attempted`, `missing_only`, `outdated_revision`, or `all`.
</ParamField>

<ParamField body="insight_config_ids" type="string[]">
  Insights to re-run. Empty means every enabled insight.
</ParamField>

<ParamField body="document_type_slugs" type="string[]">
  Only these document types.
</ParamField>

<ParamField body="vendor_ids" type="string[]">
  Only these vendors' documents.
</ParamField>

<ParamField body="document_ids" type="string[]">
  Only these documents.
</ParamField>

<ParamField body="include_manually_cleared" type="boolean" default="false">
  Re-fill values a person emptied on purpose.
</ParamField>

The preview returns `document_count`, `insight_count`, `estimated_model_calls`, `manually_cleared_count`, and `blocked_reason` when it could not start now.

To start one, send the same body to `POST /v1/document-insight-backfills`. It returns `202` with the backfill. Poll `GET /v1/document-insight-backfills/{backfill_id}` until `status` is `completed`, `failed`, or `cancelled`. A run over the per-run or per-day ceilings, or with nothing to do, returns `422`, `409`, or `429` with `backfill_refused`. To stop dispatching more documents, send `POST /v1/document-insight-backfills/{backfill_id}/cancel`. Work already started finishes.

## Escalate an exposure, sync the watchlist, and set retention

- To open a finding from an exposure, send `POST /v1/dark-web/exposures/{exposure_id}/escalate` with optional `title` and `assigned_to_id`. A second call returns the same `finding_id`.
- To re-derive the watchlist from your organization and vendor records now, send `POST /v1/dark-web/watchlist/sync`. The response counts identifiers `created`, `kept`, and `archived`.
- To read how long each class of dark web data is kept, send `GET /v1/dark-web/retention`. To change it, send `PUT /v1/dark-web/retention` with `exposures_years`, `evidence_years`, `audit_years`, and `sweep_history_years`. A shorter period purges older data at the next nightly run.

## Work with your organization's own documents

Org documents are files your organization owns, such as policies, questionnaire and report templates, and exports.

- To list them, send `GET /v1/org-documents` with optional `document_type`, `search`, `limit`, and `offset`.
- To download one, send `GET /v1/org-documents/{document_id}/download`. The response gives a presigned `url` that is valid for `expires_in` seconds. Follow it with a plain `GET` and no auth header.
- To rename, retype, archive, or restore one, send `PATCH /v1/org-documents/{document_id}` with any of `name`, `document_type`, and `is_archived`.
- To upload one, send `POST /v1/org-documents` as `multipart/form-data` with `file` and optional `document_type` and `name`. It returns `201` with the document. An `assessment_report_template` must be a valid `.docx`: another extension returns `400` with `template_must_be_docx`, and a file that does not open as Word returns `400` with `invalid_template`.

## Correct or remove extracted values

- To replace an extracted value with the right one, send `POST /v1/document-insight-values/{data_id}/correct` with one of `value_string`, `value_number`, `value_date`, or `value_boolean`. The correction becomes a manual value that no re-extraction overwrites, and Coverbase writes it to linked fields. A value that does not fit the insight's type returns `422` with `invalid_value`.
- To delete a value, send `DELETE /v1/document-insight-values/{data_id}`.
- To judge many values at once, send `POST /v1/document-insight-values/bulk-verdict` with `ids` and `verdict` (`correct`, `incorrect`, or null). The response gives `updated_count` and `found_count`; a value that already holds the verdict is skipped.
