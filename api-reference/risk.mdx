The Risk API gives you the same risk register, scenarios and reports the Risk page shows. A **risk** is an entry on the register with an inherent and a residual score, an owner, a scope and the signals (findings, contract gaps, alerts and other records) that support it.

Every endpoint is scoped to the organization of the API key. See [API conventions](/conventions) for shared behavior.

The `/v1/risks`, `/v1/risk-exposure`, `/v1/risk-report`, `/v1/risk-config` and `/v1/risk-scenarios` endpoints need the Risk module. When your organization does not have it, they return `404` with the code `not_enabled`.

Endpoints that need `org_settings:read:org` or `org_settings:update:org` work with a user API key. A service account key does not hold `org_settings`, so it receives `403` from them in an organization that enforces roles.

Archiving a risk or a scenario, and deciding on a risk the Coverbase agent proposed, stay decisions a signed-in user makes in the app. The API does not offer them.

## Errors

Errors return a `detail` object with a `code` and a `message`.

| Status | Code | When |
| ------ | ---- | ---- |
| `403` | | The key's role does not hold the permission the endpoint needs. |
| `404` | `not_enabled` | The Risk module is not enabled for your organization. |
| `404` | `risk_not_found` | No risk has that ID. |
| `404` | `signal_not_found` | The risk has no signal with that ID. |
| `404` | `scenario_not_found` | No saved scenario has that ID. |
| `404` | `risk_domain_not_found` | No risk domain has that ID. |
| `422` | `invalid_risk` | The risk is missing a description or a score is off the scale. |
| `400` | `invalid_risk_domain` | The risk domain change is not valid, for example a duplicate name. |

## Query the register

<ParamField path="method" type="POST">
  `POST /v1/risks/query`
</ParamField>

Returns one page of register risks that match the filters. Send an empty body to list every risk except closed ones.

<ParamField body="statuses" type="string[]">
  Any of `proposed`, `open`, `mitigating`, `accepted` and `closed`.
</ParamField>

<ParamField body="risk_domain_ids" type="string[]">
  Risk domains to include.
</ParamField>

<ParamField body="vendor_id" type="string">
  Only risks scoped to this vendor.
</ParamField>

<ParamField body="search" type="string">
  Text to match in the risk description.
</ParamField>

<ParamField body="limit" type="integer" default="25">
  Page size. The API caps it at 200.
</ParamField>

<ParamField body="offset" type="integer" default="0">
  Rows to skip.
</ParamField>

The body also accepts `categories`, `owner_user_ids`, `owner_department_ids`, `unowned`, `appetite`, `source_types`, `institution_key`, `service_id`, `contract_id`, `finding_id`, `review_overdue`, `proposal_kinds` and `sort`.

### Response

```json
{
  "items": [
    {
      "id": "cbrisk_...",
      "description": "Loss of the payments processor halts checkout",
      "status": "open",
      "inherent_score": 20,
      "residual_score": 12,
      "appetite": "outside",
      "owner": { "user_id": "cbuser_...", "display": "Dana Lee" },
      "signal_counts": { "open": 3, "closed": 1, "dismissed": 0 }
    }
  ],
  "total": 1,
  "limit": 25,
  "offset": 0
}
```

## Read the register summary and matrix

<ParamField path="method" type="GET">
  `GET /v1/risks/summary`
</ParamField>

Returns the register's headline numbers: risks outside appetite, open proposals, unowned risks, overdue reviews, open signals, and counts by domain, source and category.

<ParamField path="method" type="GET">
  `GET /v1/risks/matrix`
</ParamField>

Returns the likelihood by impact heat map with inherent and residual counts per cell.

<ParamField query="institution_key" type="string">
  Limit either view to one institution of a multi-entity organization.
</ParamField>

<ParamField query="risk_domain_id" type="string">
  For the matrix, limit to one risk domain.
</ParamField>

## Create a risk

<ParamField path="method" type="POST">
  `POST /v1/risks`
</ParamField>

Returns `201 Created` with the new risk and its computed scores.

<ParamField body="description" type="string" required>
  What could happen.
</ParamField>

<ParamField body="risk_domain_id" type="string">
  The risk domain the risk belongs to.
</ParamField>

<ParamField body="likelihood_level" type="integer">
  Inherent likelihood on your organization's scale. `impact_level`, `residual_likelihood_level` and `residual_impact_level` work the same way.
</ParamField>

<ParamField body="owner_user_id" type="string">
  The owning user. Use `owner_department_id` to name a business unit instead.
</ParamField>

<ParamField body="vendor_ids" type="string[]">
  Vendors in scope. `service_ids`, `department_ids`, `entity_ids` and `region_codes` set the rest of the scope.
</ParamField>

The body also accepts `category`, `status`, `treatment`, `treatment_plan`, `review_at`, `accepted_until`, `institution_key` and `note`.

## Get or edit a risk

<ParamField path="method" type="GET">
  `GET /v1/risks/{risk_id}`
</ParamField>

Returns one risk with its signals, history and the excerpt of the dependency chain behind it.

<ParamField path="method" type="PATCH">
  `PATCH /v1/risks/{risk_id}`
</ParamField>

Takes the same fields as create. Fields you omit keep their value. Returns the updated risk.

## Attach or dismiss a signal

<ParamField path="method" type="POST">
  `POST /v1/risks/{risk_id}/signals`
</ParamField>

Returns `201 Created` with the attached signal.

<ParamField body="source_type" type="string" required>
  One of `finding`, `contract`, `contract_clause`, `contract_component_gap`, `obligation`, `screening_match`, `radar_signal`, `radar_alert`, `vendor_risk_change`, `inspect_evaluation`, `assessment` and `supplier_site`.
</ParamField>

<ParamField body="source_id" type="string" required>
  The ID of the record.
</ParamField>

<ParamField body="rationale" type="string">
  Why the record supports this risk.
</ParamField>

<ParamField path="method" type="POST">
  `POST /v1/risks/{risk_id}/signals/{signal_id}/dismiss`
</ParamField>

Dismisses the signal and returns it. The signal stays on the risk's history.

## Read exposure, the board report and the configuration

<ParamField path="method" type="GET">
  `GET /v1/risk-exposure`
</ParamField>

Returns appetite gauges per risk domain, the loss model, the contractual cushion, and fourth party, business unit and geographic concentration. Pass `institution_key` to limit the domain gauges to one institution.

<ParamField path="method" type="GET">
  `GET /v1/risk-report`
</ParamField>

Returns the board report: KRI tiles, movers, appetite breaches, domains, framework coverage and commitments on time. Pass `period` with a key from the response's `periods` to read an earlier period.

<ParamField path="method" type="GET">
  `GET /v1/risk-config`
</ParamField>

Returns the Risk module configuration: appetite thresholds, taxonomy, quantification, likelihood and impact levels, domain appetite, signal sources and agent settings.

## Run and save scenarios

<ParamField path="method" type="POST">
  `POST /v1/risk-scenarios/run`
</ParamField>

Runs a what-if scenario over the dependency chain and returns its blast radius, obligations, findings on the path and loss estimate. Nothing is saved.

<ParamField body="inputs" type="object" required>
  The scenario. Set `kind` to `event`, `change` or `offboard`, name the subject with `subject_vendor_id` or `subject_node_id`, or send a plain-English `prompt` such as "Okta is down for 24 hours".
</ParamField>

<ParamField path="method" type="POST">
  `POST /v1/risk-scenarios`
</ParamField>

Returns `201 Created` with the saved scenario. Send `inputs`, an optional `title`, and the `result` of a run. When you omit `result`, Coverbase runs the scenario once and saves what it returns, which also needs `risk:run:org`.

<ParamField path="method" type="GET">
  `GET /v1/risk-scenarios`
</ParamField>

Lists saved scenarios, newest first, with `limit` (at most 200) and `offset`.

<ParamField path="method" type="GET">
  `GET /v1/risk-scenarios/{scenario_id}`
</ParamField>

Returns one saved scenario with its inputs and result.

## Manage risk domains

<ParamField path="method" type="GET">
  `GET /v1/risk-domains`
</ParamField>

Lists your organization's risk domains with `limit` (at most 200) and `offset`. Pass `include_archived=true` to include archived domains.

<ParamField path="method" type="POST">
  `POST /v1/risk-domains`
</ParamField>

Returns `201 Created` with the new domain. Coverbase records the change on the domain's activity feed.

<ParamField body="name" type="string" required>
  The domain's name, 1 to 255 characters.
</ParamField>

<ParamField body="description" type="string">
  What the domain covers, up to 1000 characters.
</ParamField>

<ParamField body="weight" type="number">
  The domain's weight in the weighted roll-up, from 0 to 100.
</ParamField>

<ParamField body="reviewer_ids" type="string[]">
  Users who review the domain. Use `department_reviewer_ids` for user groups.
</ParamField>

<ParamField path="method" type="PATCH">
  `PATCH /v1/risk-domains/{risk_domain_id}`
</ParamField>

Takes the same fields as create. Fields you omit keep their value, and an explicit `null` for `weight` takes the domain out of the roll-up. To archive a domain, a signed-in user does it in the app.

## Read a vendor's risk score history

<ParamField path="method" type="GET">
  `GET /v1/vendors/{vendor_id}/risk-score-history`
</ParamField>

Lists how a vendor's overall and per-domain risk scores changed, newest first, with `limit` (at most 200) and `offset`. An entry with a null `risk_domain_id` is the vendor's overall score.

## Read methodology and AI governance

These reads need the TPRM lifecycle. When your organization does not have it, they return `404` with the code `not_enabled`.

<ParamField path="method" type="GET">
  `GET /v1/risk-methodology`
</ParamField>

Returns `irq_aggregation_method`, which decides how inherent risk questionnaire answers aggregate into a score.

<ParamField path="method" type="GET">
  `GET /v1/reviewer-matrix-rules`
</ParamField>

Returns the reviewer matrix in `data`. Each rule names a requester group, risk level, risk domain and business unit (a null criterion matches anything) and one reviewing user or group.

<ParamField path="method" type="GET">
  `GET /v1/work-queue-escalation-rules`
</ParamField>

Returns the rules that escalate overdue work queue items in `data`.

<ParamField path="method" type="GET">
  `GET /v1/ai-settings`
</ParamField>

Returns PII redaction, learning, evaluation guidance, each agent policy and the privacy posture.

<ParamField path="method" type="GET">
  `GET /v1/agent-actions`
</ParamField>

Lists the Agent Ledger, newest first. Filter with `awaiting_decision`, `target_type` and `target_id`, and page with `limit` (at most 200) and `offset`. Deciding an action stays with a signed-in user.

## Read access removal requests

<ParamField path="method" type="GET">
  `GET /v1/vendors/{vendor_id}/access-removal-requests`
</ParamField>

Lists the identity-provider access removals a workflow proposed for a vendor, with each assignment it would remove. This read needs Inspect and returns `404` when Inspect is not enabled. Approving or rejecting a request stays with a signed-in user.

## Change configuration and methodology

<ParamField path="method" type="PATCH">
  `PATCH /v1/risk-config`
</ParamField>

Changes the Risk module configuration and returns it. Only the fields you send change. An invalid level scale returns `422` with the code `invalid_risk_config`.

<ParamField path="method" type="PUT">
  `PUT /v1/risk-methodology`
</ParamField>

Sets `irq_aggregation_method` and returns it.

<ParamField path="method" type="POST">
  `POST /v1/reviewer-matrix-rules`
</ParamField>

Returns `201 Created` with the new rule. Send `requester_department_id`, `risk_level_id`, `risk_domain_id` and `business_unit_id` (a null criterion matches anything) and one of `reviewer_user_id` or `reviewer_department_id`. `PUT /v1/reviewer-matrix-rules/{rule_id}` replaces a rule with the same body.

<ParamField path="method" type="POST">
  `POST /v1/work-queue-escalation-rules`
</ParamField>

Returns `201 Created` with the new rule. Send `name`, `overdue_days` (0 to 365), `target_type`, `item_types` (empty covers every type), `target_user_id` or `target_department_id`, and `reassign`. `PUT /v1/work-queue-escalation-rules/{rule_id}` replaces a rule with the same body.

<ParamField path="method" type="PATCH">
  `PATCH /v1/ai-settings`
</ParamField>

Changes `pii_redaction_enabled`, `learning_enabled`, `evaluation_guidance` (null clears it) or `policies`, and returns the settings. A policy that always needs a person, or that no agent enforces yet, returns `400` with the code `policy_not_allowed`.

`GET /v1/ai-settings/learned-examples` lists the examples the org's reviewers taught control evaluation, newest first.

## Other reads and actions

`POST /v1/risks/{risk_id}/commitment-requests` asks a risk's owner to commit to treating it. Send an optional `due_at` and `message`. It returns `201 Created` with the `finding_id` and `commitment_id` it created.

`POST /v1/risk-chain/query` returns the dependency chain. Send the same filters the Risk page uses, such as `follow`, `depth`, `critical_only` and `focus_node_id`.

`GET /v1/access-removal-requests/{request_id}` returns one access removal request.

`GET /v1/vendors/{vendor_id}/due-diligence-status` returns `is_current`, the latest completed assessment and the next assessment date. It needs the TPRM lifecycle.

`GET /v1/findings-stats` returns the Findings page's insight numbers over every finding.

`POST /v1/commitments/{commitment_id}/extend-due-date` moves a mitigation-underway commitment's `due_at` later and stores an optional internal `note`. The vendor's acceptance stands. A commitment that is not mitigation-underway, or a date that is not later, returns `400` with the code `extension_not_allowed`.

## Questionnaire versions

These need the TPRM lifecycle. `GET /v1/questionnaire-versions` lists versioned templates; pass `types` (default `irq`). `POST /v1/questionnaires/{questionnaire_id}/draft-version` returns `201 Created` with a new draft copied from that version. `POST /v1/questionnaires/{questionnaire_id}/publish-version` publishes a draft so new sends use it.

## Responsibilities

These need Responsibilities enabled for your organization, and return `404` with the code `not_enabled` otherwise.

`GET /v1/responsibility-topics` lists the topics in template order. `POST /v1/responsibility-topics` returns `201 Created` with a new topic. Send `label`, `question`, and optionally `guidance`, `default_iaas`, `default_paas`, `default_saas` and `owner_department_id`.

`GET /v1/vendors/{vendor_id}/responsibility-matrix` returns the vendor's matrix, its current version and its version history. Pass `engagement_id` for an engagement's matrix. It returns `404` with the code `responsibility_matrix_not_found` until a matrix is saved.

`POST /v1/vendors/{vendor_id}/responsibility-matrix` saves `columns`, `rows`, `cells` and an optional `note` as a new published version and returns the matrix.

## Attestations and review sessions

`GET /v1/questionnaires/{questionnaire_id}/responses/{response_id}/attestation` returns the questionnaire's attestation config, every record on the response, and `is_satisfied`. Signing an attestation stays with a person.

`GET /v1/assessments/{assessment_id}/review-sessions` lists the remote and onsite review sessions on an assessment. It needs the TPRM lifecycle.

## Work queue items

The work queue holds tasks assigned to people, such as reviewing an assessment. A key reaches the items assigned to its own user; an admin user key reaches every item.

`GET /v1/work-queue-items` lists items, newest first. Filter with `statuses`, `types`, `vendor_id` and `assessment_id`, and page with `limit` (at most 200) and `offset`. `GET /v1/work-queue-items/{work_queue_item_id}` returns one item. An item the key cannot reach returns `403` with the code `work_queue_item_forbidden`.

`POST /v1/work-queue-items/{work_queue_item_id}/complete` marks an item complete. An item a record owns resolves with that record and returns `409` with the code `work_queue_item_conflict`. `POST /v1/work-queue-items/{work_queue_item_id}/reopen` puts a completed item back to pending.
