These endpoints extend the [contract records](/api-reference/contract-records) and [engagement records](/api-reference/engagement-records) APIs. Every endpoint is scoped to the organization that owns the API key. See [API conventions](/conventions) for shared behavior.

List endpoints take `limit` and `offset` and return `items`, `total`, `limit` and `offset`. Errors return `detail` with a `code` and a `message`.

## List cost centers

`GET /v1/cost-centers` returns the cost center codes your contracts can carry.

<ParamField query="include_archived" type="boolean" default="false">
  Include archived codes.
</ParamField>
<ParamField query="limit" type="integer" default="200">
  Page size, 1 to 2000.
</ParamField>
<ParamField query="offset" type="integer" default="0">
  Rows to skip.
</ParamField>

Each item has `id`, `code`, `description` and `is_archived`.

## List business units

`GET /v1/business-units` returns your business units in the order your organization set. It takes the same parameters as the cost center list. Each item has `id`, `code`, `name`, `parent_id` and `is_archived`.

## List procurements

`GET /v1/procurements` returns procurement requests, newest first.

<ParamField query="vendor_id" type="string">
  Only procurements for this vendor.
</ParamField>
<ParamField query="status_id" type="string">
  Only procurements in this workflow status.
</ParamField>
<ParamField query="search" type="string">
  Text to match in the title.
</ParamField>
<ParamField query="include_archived" type="boolean" default="false">
  Include archived procurements.
</ParamField>
<ParamField query="limit" type="integer" default="50">
  Page size, 1 to 500.
</ParamField>

Each item has `id`, `title`, `description`, `vendor_id`, `status_id`, `status`, `priority`, `assignee_id`, `assignee_group_id`, `assessment_ids`, `contract_ids`, `intake_session_ids`, `is_archived`, `created_at` and `updated_at`.

## Get a procurement

`GET /v1/procurements/{procurement_id}` returns one procurement in the same shape. An unknown ID returns `404` with code `procurement_not_found`.

## List a vendor's purchase orders

`GET /v1/vendors/{vendor_id}/purchase-orders` returns the vendor's purchase orders, newest first. `total` counts all of the vendor's purchase orders.

<ParamField query="limit" type="integer" default="25">
  Page size, 1 to 200.
</ParamField>

## Get a purchase order

`GET /v1/purchase-orders/{purchase_order_id}` returns one purchase order with its three-way match. Each entry in `lines` compares the PO amount with the first receipt line and the first invoice line that carry the same line number. A line is `matched` when all three amounts agree within one cent, `open` while a receipt or invoice amount is missing, and `exception` otherwise. `match_status` is `exception` when any line is, `matched` when every line is, and `open` otherwise. An unknown ID returns `404` with code `purchase_order_not_found`.

## Create a purchase order

`POST /v1/purchase-orders` creates a draft purchase order and returns `201`.

<ParamField body="vendor_id" type="string" required>
  The vendor ID.
</ParamField>
<ParamField body="po_number" type="string">
  The PO number. It must be unique in your organization.
</ParamField>
<ParamField body="assessment_id" type="string">
  The assessment the purchase order follows from.
</ParamField>
<ParamField body="total_amount" type="string">
  The total as a decimal string, for example `"1200.00"`.
</ParamField>
<ParamField body="currency" type="string" default="USD">
  ISO currency code.
</ParamField>
<ParamField body="line_items" type="object[]">
  Each line has `description`, `quantity`, `unit_price` and `amount`.
</ParamField>
<ParamField body="external_system" type="string">
  The system of record that also holds the purchase order.
</ParamField>

Errors: `400` with code `vendor_not_found`, `409` with code `po_number_taken`, and `422` with code `assessment_not_for_vendor` when `assessment_id` is not an assessment of that vendor.

## Issue a purchase order

`POST /v1/purchase-orders/{purchase_order_id}/issue` moves a draft to issued.

<ParamField body="po_number_format" type="string">
  The format for a generated PO number, for example `PO-{YEAR}-{SEQ}`.
</ParamField>

Coverbase refuses the call with `409` while the vendor fails a blocking prequalification rule.

## Read and file offboarding

The engagement lifecycle endpoints return `404` with code `not_enabled` when your organization does not have the engagement lifecycle, and `404` with code `engagement_not_found` for an unknown engagement.

`GET /v1/engagement-records/{engagement_id}/offboarding` returns `request`, the latest offboarding request, or `null`. The request has `id`, `status`, `reason_category`, `justification`, `requested_date`, `required_approval_roles`, the approval times, and the start, completion and cancel times.

To file an offboarding request, send `POST /v1/engagement-records/{engagement_id}/offboarding`. Coverbase notifies the approvers and returns `201` with the new state.

<ParamField body="reason_category" type="string" required>
  One of `consolidation`, `contract_end`, `no_longer_needed`, `performance`, `risk`, `cost` or `other`.
</ParamField>
<ParamField body="justification" type="string" required>
  Why the engagement ends, up to 4000 characters.
</ParamField>
<ParamField body="requested_date" type="integer">
  When offboarding should happen, in Unix seconds.
</ParamField>

A request the lifecycle refuses, for example a second open request, returns the refusal's `code` and `message`.

## Continuity plan

`GET /v1/engagement-records/{engagement_id}/continuity-plan` returns the plan. Before anyone saves one, every field except `engagement_id` is empty.

To create or edit the plan, send `PUT /v1/engagement-records/{engagement_id}/continuity-plan`. Fields you leave out stay as they are. An explicit `null` for `rto_hours` clears it.

<ParamField body="owner_user_id" type="string">
  The plan owner. The user must belong to your organization, or the call returns `400` with code `user_not_in_org`.
</ParamField>
<ParamField body="backup_suppliers" type="object[]">
  Up to 20 entries, each with `name`, `vendor_id` and `notes`.
</ParamField>
<ParamField body="exit_strategy" type="string">
  How you would exit the vendor, up to 10000 characters.
</ParamField>
<ParamField body="rto_hours" type="integer">
  Recovery time objective in hours, 0 to 8760.
</ParamField>
<ParamField body="resiliency_notes" type="string">
  Free-form notes, up to 10000 characters.
</ParamField>
<ParamField body="transition_steps" type="string[]">
  Up to 50 ordered steps.
</ParamField>

To submit the plan for review, send `POST /v1/engagement-records/{engagement_id}/continuity-plan/submit`.

## Clause sets

A clause set is the playbook a contract clause review compares against. Each reference clause carries up to five risk-tier variants.

`GET /v1/clause-sets` lists your clause sets with their current reference clauses. It takes `include_archived`, `limit` (1 to 200, default 50) and `offset`. `GET /v1/clause-sets/{clause_set_id}` returns one set. An unknown ID returns `404` with code `clause_set_not_found`.

To create a set, send `POST /v1/clause-sets` with `name`, and optionally `description`, `is_active` and `library_template_id` to copy a shipped template. To change a set, send `PATCH /v1/clause-sets/{clause_set_id}` with any of `name`, `description`, `is_active` and `public_id_prefix` (up to 16 characters). An explicit `null` clears `description` or `public_id_prefix`. A change to an archived set returns `409` with code `clause_set_archived`.

To add a reference clause, send `POST /v1/clause-sets/{clause_set_id}/reference-clauses`.

<ParamField body="public_id" type="string" required>
  The clause's ID in the playbook, for example `DPA-01`.
</ParamField>
<ParamField body="name" type="string" required>
  The clause name.
</ParamField>
<ParamField body="category" type="string" required>
  The clause category.
</ParamField>
<ParamField body="severity" type="string" required>
  `low`, `medium`, `high` or `critical`.
</ParamField>
<ParamField body="variants" type="object[]">
  Each variant has `risk_tier` (1 to 5), `label`, `text` and `is_archived`. Active variants need distinct tiers, or the call returns `422` with code `duplicate_risk_tier`.
</ParamField>

`PATCH /v1/clause-sets/{clause_set_id}/reference-clauses/{reference_clause_id}` saves a new version of the clause and returns it with its new `id`. Variants you send replace the current ones.

To reorder, send `POST /v1/clause-sets/{clause_set_id}/reference-clauses/reorder` with `reference_clause_ids` listing every current clause once. Any other list returns `422` with code `invalid_order`.

API keys cannot archive. `DELETE` on a clause set or a reference clause with an API key returns `403` with code `api_key_not_allowed`.

## Clause reviews

A clause review compares a contract's documents with clause sets and records a match for each reference clause.

To start one, send `POST /v1/contract-records/{contract_id}/clause-reviews` with `clause_set_ids` and, optionally, `document_ids`. Coverbase returns `202` and runs the review in the background. Poll `GET /v1/contract-records/{contract_id}/clause-reviews/{run_id}` until `status` is `completed` or `failed`. Pass `latest` as `run_id` for the most recent run. If the contract already has an active run over the same clause sets, you get that run. An active run over different clause sets returns `409` with code `active_run_exists`. An unknown or inactive clause set returns `404` with code `clause_set_not_found` or `422` with code `clause_set_not_usable`.

Each match has `status`, `triage_decision`, `triage_notes`, `confidence`, `extracted_text`, `reasoning`, `source_document_id` and `page_num`.

To record a reviewer's verdict, send `PATCH /v1/clause-matches/{match_id}` with either `status` (`conforming`, `needs_review`, `non_conforming`, `missing`, `not_applicable` or `accepted_risk`, plus `accepted_risk_expires_at`) or `triage_decision` (`no_action`, `accepted_risk` or `false_positive`, plus `triage_notes`). Accepting a risk is a sign-off, so an API key gets `403` with code `api_key_not_allowed`.

To set one triage decision on up to 500 matches, send `POST /v1/clause-matches/triage` with `match_ids`, `decision` and optional `notes`. Each match is decided on its own: the response lists `succeeded_match_ids` and `failures`, each with a `match_id` and a `message`.

## Findings from clause matches

To raise one finding from up to 200 of a contract's clause matches, send `POST /v1/contract-records/{contract_id}/findings-from-clause-matches` with `clause_match_ids` and `title`, and optionally `body`, `assigned_to_id`, `due_date`, the severity, urgency and risk level IDs, and `finding_status_id`. Coverbase returns `201` with `finding_id` and sets each match's triage to `action_created`.

To link a match to an existing finding, send `POST /v1/clause-matches/{match_id}/finding-links` with `finding_id`. To remove a link, send `POST /v1/clause-match-finding-links/{association_id}/unlink` with `next_triage`: `leave`, `clear`, `no_action`, `accepted_risk` or `false_positive`. Setting `accepted_risk` with an API key returns `403` with code `api_key_not_allowed`.

## Follow-up drafts

To have Coverbase AI draft a follow-up from clause matches, send `POST /v1/contract-records/{contract_id}/follow-up-drafts` with `clause_match_ids` (1 to 200), `audience` (`vendor` or `procurement`) and `force`. Coverbase returns `202` and writes the draft in the background. Poll `GET /v1/contract-records/{contract_id}/follow-up-drafts/{draft_id}` until `status` is `completed` or `failed`, then read `draft_text`. Coverbase sends nothing to anyone. A match from another contract returns `422` with code `foreign_clause_match`.
