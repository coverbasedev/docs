Inspect runs on the same platform, in the same region, under the same encryption, tenancy and retention controls as the rest of Coverbase. This page covers only what is specific to Inspect: the browser host, the models, and the evidence it produces. For the platform controls, see [Data protection](/security/data-protection) and [AI governance](/security/ai-governance).

## Components and where they run

| Component | Where it runs | Operated by |
| --- | --- | --- |
| Coverbase application, database, object storage, workers | AWS, United States (`us-east-1`) | Coverbase |
| API evidence requests | Coverbase workers in the same AWS environment | Coverbase |
| Browser sessions for browser evidence and sign-in | Browserbase, a managed browser service, in its US region | Browserbase, under Coverbase's account |
| Models | AWS Bedrock, Anthropic Claude models, through Coverbase's AWS account | AWS |
| Credentials and secrets | AWS Secrets Manager under AWS KMS keys, in Coverbase's account | Coverbase |

<Note>
  **Browser hosting is a third-party service today.** Browser sessions run in stock Chrome provided by Browserbase and are controlled from Coverbase workers over the Chrome DevTools Protocol. Coverbase installs its own read-only enforcement on each session after sign-in. There is no custom or hardened browser build. Browserbase is on Coverbase's subprocessor list, available on request.
</Note>

## Planned: Coverbase-operated browser infrastructure

Coverbase is planning to move Inspect's browser execution onto infrastructure Coverbase operates itself, so that browser hosting, session recording and redaction sit inside the same boundary as the rest of the platform. This is an active engineering workstream without a committed cutover date. It is **Coverbase-hosted**, not customer-hosted: a runner deployed inside a customer's own network is not on the roadmap. If your program requires either, say so during evaluation so it can be scoped rather than assumed.

## Models

- **Which models.** Inspect uses Anthropic Claude models served by AWS Bedrock. The browser agent, the sign-in agent, network and navigation adjudication, plan preparation and evaluation all run through Bedrock within Coverbase's AWS account.
- **Cross-region inference.** Inspect calls Bedrock through a cross-region inference profile. AWS may serve an individual request from a Bedrock region other than `us-east-1`. Requests and responses stay within AWS and within Coverbase's account; no data is sent to a consumer AI endpoint. If your program requires inference pinned to a single region, raise it during evaluation.
- **No training on your data.** Customer data sent to Bedrock is not used to train the foundation models. See [AI governance](/security/ai-governance).
- **Invocation logging.** Coverbase keeps Bedrock invocation metadata (model, timing, token counts) for 90 days for capacity and reliability monitoring. Prompt and response text is not delivered to that log.

## What the models see

| Input | Sent to the model? |
| --- | --- |
| Vendor documentation, during plan preparation | Yes |
| The control's expectation and instructions | Yes |
| The admin console page the agent is on (text and structure), during a browser step | Yes |
| Evidence screenshots | No. Screenshots are captured by code for a human reviewer, and the agent runs without vision. |
| Credentials, one-time codes, passkeys | No. Sign-in completes before the collecting agent starts, and factor values are entered by the runtime, not the model. |
| Outbound request bodies, during network adjudication | A reduced form: field paths and operation-like literals are kept; credentials, identifiers, long text and query values are replaced with redaction markers. |
| Navigation targets | The address path and query parameter names, never query values. |
| Collected observations, during evaluation | Yes, for Evaluate inspections only. |

## What is stored, where, and for how long

| Data | Where | Retention |
| --- | --- | --- |
| Observations, evaluations, comparisons, activity events | Coverbase database, scoped to your organization | Life of the subscription, under your agreement's retention terms |
| Evidence screenshots | Coverbase object storage, encrypted at rest | Same as the inspection that produced them. Screenshots from an attempt that did not complete are deleted. |
| Browser session recordings (replays) | Browserbase | Governed by Browserbase's retention. Played back inside Coverbase; confirm the period with your Coverbase team if it matters to your program. |
| Stored browser sign-in profiles | Browserbase | Deleted after 12 hours without use |
| Target credentials, API tokens, one-time-code seeds, passkeys | AWS Secrets Manager under KMS | Until you remove the target or rotate the secret. Never returned by any API. |
| Bedrock invocation metadata | Coverbase AWS account | 90 days |
| Application logs | Coverbase logging | Platform retention. URLs are redacted before logging; no credential or page content is logged. |

## Redaction

What is redacted today, and what is not:

- **Redacted:** URLs in logs and events; request bodies before the network judge sees them; credentials and secrets everywhere.
- **Not redacted:** evidence. Screenshots and observed records are stored as captured, because they are the evidence a reviewer and an auditor need to see. If a control's evidence would include personal data (a member list, an email address in an audit log), that data is stored in Coverbase alongside the observation.

<Warning>
  Do not plan a trial on the assumption that Inspect strips sensitive values from evidence. Pick the control set with that in mind, or start with controls whose evidence is configuration rather than people.
</Warning>

Redaction of model-generated progress summaries before they are stored is a planned improvement. Evidence-level redaction is being considered as part of the Coverbase-operated browser work above; neither is available today.

## Residency

The multi-tenant Coverbase environment runs in the United States, and Inspect's browser host is configured for its US region. Coverbase's stack is defined as infrastructure-as-code and parameterized by region, so a deployment in another region is a configuration of the same stack rather than a rebuild; no such deployment exists today. Cross-region model inference is described above. Programs with a specific residency obligation should raise it during evaluation.
