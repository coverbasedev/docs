A Zero Touch Assessment answers one question cheaply: **is anything obviously wrong with this vendor?**

It is an ordinary assessment on the ordinary pipeline — same controls, same issues, same evidence — with three differences that make it a triage tool rather than a review:

<CardGroup cols={3}>
  <Card title="Nobody is contacted" icon="envelope-open">
    No document request, no questionnaire, no waiting on a vendor to reply. A run completes against public research and whatever evidence is already on file.
  </Card>
  <Card title="It doesn't draw down quota" icon="wallet">
    Zero Touch runs are excluded from your assessment allowance, so covering a long tail of vendors costs nothing.
  </Card>
  <Card title="It produces one number" icon="gauge">
    A single Zero Touch Score, so a batch of vendors can be ranked rather than read one by one.
  </Card>
</CardGroup>

## When to reach for one

Zero Touch is a **filter**, not a replacement for a full assessment. It is the right tool when:

- A new vendor arrives and you need to know whether to spend a real review on it.
- You have inherited a portfolio and have no idea which vendors are risky.
- A renewal is coming up and you want a cheap re-check since the last review.
- Someone asks "are we exposed to this vendor?" and you need an answer today.

It is the **wrong** tool when you need assurance you can show an auditor. A run has never spoken to the vendor, so it cannot confirm a control is operating — only that public evidence does or does not support it.

## Running one

<Steps>
  <Step title="Pick your vendors">
    From **Zero Touch Assessment → Launch**, choose one vendor or many. You can also start from a vendor's own page, or select rows in the vendors table and launch the whole selection at once.
  </Step>
  <Step title="Confirm">
    The second step has no inputs on purpose. Everything else — which controls are in scope, what feeds the score, where the score goes — is configured once for your organization, so every run stays comparable with every other run.
  </Step>
  <Step title="Come back to the ranked view">
    Runs complete on their own. The module page's default view ranks one row per vendor by score, which is the order to work them in.
  </Step>
</Steps>

## Reading a result

Open any run to get a single-page fact sheet. Read it in this order:

<Steps>
  <Step title="The composite, then what it's made of">
    The headline number combines up to three independently-sourced components: the control evaluation, the vendor's Financial Health Score, and its outside-in security rating. Each is scored 0–100 on its own before anything is combined.
  </Step>
  <Step title="Check which components actually resolved">
    **A component with no data is left out, never counted as zero.** A vendor with no filed financials has not failed the financial component — it has no financial component, and the remaining weights are redistributed across what did resolve. The card tells you both the weight it was configured with and the share it actually carried.

    <Warning>
      This is the most common misreading. A vendor scoring 78 on one component is not comparable to a vendor scoring 78 on three. Check the composition before ranking two vendors against each other.
    </Warning>
  </Step>
  <Step title="Work the issues">
    Each open issue carries the evidence behind it and the control set that raised it. This is the part that tells you *what* is wrong, as opposed to *how much*.
  </Step>
  <Step title="Check the sources">
    Every place the run drew evidence from is listed, grouped by kind — web research, registries and filings, vendor infrastructure, and documents already on file. If a conclusion looks wrong, this is where you check its provenance.
  </Step>
</Steps>

## Deciding what happens next

A result page is a decision point, and there are three reasonable exits:

<CardGroup cols={3}>
  <Card title="Accept it" icon="check">
    The vendor is low-risk enough that a full review isn't warranted right now. The score can be written onto the vendor's risk score automatically — see below.
  </Card>
  <Card title="Escalate" icon="arrow-up-right-from-square">
    **Start full assessment** from the result page carries the vendor straight into a normal assessment, with the triage findings already on the record.
  </Card>
  <Card title="Re-score" icon="rotate">
    Financial and security inputs refresh on their own schedule. **Re-score** recomputes the composite against today's data without re-running the controls.
  </Card>
</CardGroup>

## Where the score goes

By default the Zero Touch Score stays on the run. Your administrator can point it at a risk score instead, from **Scoring** on the module page:

| Setting | Effect |
| --- | --- |
| Don't apply the score | The score stays on the run and changes nothing else. |
| Vendor inherent / residual | Written onto the vendor's risk score when a run completes. |
| Service inherent / residual | Written onto each service the run covered. |

Only the axis you choose is written, so a Zero Touch run can never overwrite an inherent score your team set deliberately from an intake questionnaire.

<Note>
  A vendor-scoped run configured to write a *service* score writes nothing, and says so on the result. Guessing which service was meant would move the wrong number.
</Note>

## Tuning what feeds the score

Also under **Scoring**: which signals count, and how heavily.

- Toggle the financial health and security components on or off for your organization.
- Set relative weights. They are not percentages — they're renormalised over whichever components resolve for a given vendor, which is why a vendor missing one component still scores out of a full 100.

Control scope is set by Coverbase rather than per-organization, so a free run always evaluates a known, fixed set of controls.

## Things worth knowing

<AccordionGroup>
  <Accordion title="Why is my ranked view empty right after a bulk launch?">
    It shouldn't be — in-flight runs appear immediately and sort below scored ones. If it is genuinely empty, no Zero Touch runs exist yet for this organization.
  </Accordion>
  <Accordion title="Do Zero Touch runs show up in my normal assessments list?">
    Yes. A Zero Touch run *is* an assessment. The vendor's Assessments tab splits into **Full** and **Zero Touch**, and the Full list excludes triage runs so a first pass is never mistaken for a completed review.
  </Accordion>
  <Accordion title="Why did a control come back unevaluated?">
    Because no public evidence spoke to it. That is a real result, not a failure — it tells you the question can only be answered by asking the vendor, which is what a full assessment is for.
  </Accordion>
  <Accordion title="Can I re-run a vendor?">
    Yes, as often as you like — the runs don't consume quota. The ranked view always shows the most recent run per vendor.
  </Accordion>
</AccordionGroup>
