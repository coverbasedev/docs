An envelope is one agreement, out for signature, addressed to named people. It is the only object here that is binding, and it is the one that carries the evidence.

## Start an envelope

**New Envelope** on **Contracts → Signatures** opens a four-step wizard. You can also start one from a contract's own signatures tab, which fills the vendor in for you.

### Step 1 — the document

<Frame caption="Step 1. Name the envelope, choose its paper, file it against a vendor, and set how long it stays open.">
  <img src="/images/user-guides/signing-wizard-document.png" alt="Send wizard step one showing envelope name, template picker, associated vendor and expiration" />
</Frame>

**Envelope Name** is the subject line signers see and the name the executed copy is filed under. Make it something the counterparty will recognize in a crowded inbox.

Then pick the paper. **From a template** copies a template's roles and field layout across. **From a document**, **From a contract** and **Upload** all start you with paper and no fields, which you place yourself in step 3.

**Associated vendor** files the agreement against a counterparty. It is worth setting even when it feels obvious: it is what puts the envelope on that vendor's record, and it is what pre-fills a **Company** field for the signer.

**Expiration** starts at 30 days, or at whatever the template or your organization's settings specify. Change the number, or switch to **Expires on** and pick a date.

<Note>
  The unit selector next to the number changes how the deadline is written, not what it is. If the day count does not divide evenly into weeks or months the selector stays on days rather than showing you a rounded figure that disagrees with what will actually be sent.
</Note>

### Step 2 — the recipients

<Frame caption="Step 2. Each card is one party: who they are, what they do, when they are asked, and whether they have to prove who they are.">
  <img src="/images/user-guides/signing-wizard-recipients.png" alt="Send wizard recipients step showing name, email, private note, recipient type, signing step and identity check for a party" />
</Frame>

If you are signing something yourself and nobody else is involved, turn on **I am the only signer** at the top. It sends the envelope to you alone in a single step, and drops any other party you had added.

Otherwise, each party gets a card. Four kinds:

| Type | What they do |
| --- | --- |
| **Signer** | Signs. The envelope is not complete until every signer has. |
| **Approver** | Approves rather than signs. Blocks the envelope the same way a signer does, but applies no signature. |
| **Witness** | Signs as a witness to another party. Blocks like a signer. |
| **Copied** | Receives the agreement for information. Never blocks, and never has fields. |

Name and email autocomplete from contacts already on the associated vendor, so a party you have dealt with before is two keystrokes.

**Signs in step** is the routing order — it reads **Approves in step** on an approver. Parties in step 1 are asked immediately; step 2 is notified when step 1 finishes, and so on. Give two parties the same step and they are asked at the same time. Drag a card by its handle to reorder the list.

<Warning>
  A copied party has no step number, because copies go out the moment the envelope is sent regardless of routing. Their card reads **Delivery — emailed a copy when the envelope is sent**. If you need someone to receive the agreement only after it is executed, a copied party is not that.
</Warning>

**Private Note** is a line only that one recipient sees. It is the place for "this is the revised schedule we discussed" without putting it in front of everybody else on the envelope.

**Identity Check** is per party, and defaults to **None**. Set it to **Access code** and Coverbase generates a code for that recipient, which they must enter before the document opens.

<Warning>
  Send an access code to the signer by some other channel — a call, a text, anything that is not the signing email. Coverbase stores it as a digest and never shows it again once the envelope is sent, so copy it before you send. The refresh icon beside the field mints a new one if you lose it.
</Warning>

If a template supplied the roles, the seats are already there and you are only filling in names and addresses. Fields follow the role, so changing who sits in a seat keeps their placements.

### Step 3 — the fields

Same canvas as the template builder: parties down the left, palette below them, document in the middle, inspector on the right. If you came from a template the fields are already placed and this step is a review; if you came from a bare document, this is where you place them.

<Frame caption="Step 3. Placing fields on the envelope itself, for envelopes that did not come from a template.">
  <img src="/images/user-guides/signing-wizard-fields.png" alt="Send wizard fields step with the document canvas and field palette" />
</Frame>

Everything in [the field types](/user-guides/signature-templates#what-the-field-types-do) applies here unchanged.

### Step 4 — review and send

<Frame caption="Step 4. The signing order, the email that carries it, and the two switches that decide how it goes out.">
  <img src="/images/user-guides/signing-wizard-review.png" alt="Send wizard review step showing signing order, signing emails, signature meaning and the notify and authenticate toggles" />
</Frame>

**Signing Order** at the top is the last look at who is asked, in what order, and how many fields each one owns. The step numbers are still editable here and the rows still drag, so a routing mistake spotted at the end does not send you back a step.

**Signing Emails** is the invitation. **Subject** and **Opening line** both fall back to Coverbase's built-in wording if you leave them blank, and **Rewrite** drafts both from the document itself, which is usually a better starting point than a blank box.

**What does signing mean?** is recorded with every signature on the envelope. Most agreements do not need it; regulated workflows do, and some organizations require it on every envelope — the step says so if yours does.

Two switches decide how it goes out:

| | |
| --- | --- |
| **Email recipients the signature link** | On by default. Turn it off and links are minted but not sent, for when you are handing them out yourself. |
| **Authenticate signers' identity** | Whether a party must verify their email address before the document opens. Starts at your organization's setting and can be changed for this envelope alone. |

**Send for signature** emails the first routing step and mints each party a permanent portal address.

## Track what is out

The envelope's **Overview** tab is the working view. Down the middle: the source document with **Open the original**, **Download full packet** and **Verify now**, and under it **Fields and Values** — every field, whose it is, what it holds, which page it sits on and when it was filled. Down the right: the signing order, the envelope's details, and the portal link.

<Frame caption="An envelope in flight. Signing Order reads party by party, and Fields and Values shows what has actually been entered.">
  <img src="/images/user-guides/signing-envelope-overview.png" alt="Envelope detail overview showing document actions, fields and values, signing order, details and portal link" />
</Frame>

**Signing Order** is where you look when someone asks "where is this?" It reads per party — approved, opened but not signed, not yet asked — rather than as one envelope-level status. The badge beside the envelope name says which template version it came from.

**Details** carries the vendor the agreement is filed against, when it was sent, when it expires, when it completed, and how many documents it holds. The vendor can be changed from here if it was set wrong.

<Warning>
  The **portal link** is a permanent address for the agreement, and anyone holding it can open the document. It is there for the times you have to hand an agreement over out of band — treat it like the document itself, not like an internal reference.
</Warning>

### Nudging, correcting, cancelling

<AccordionGroup>
  <Accordion title="Send Reminder">
    Resends a reminder link to the parties currently pending. It does not touch anyone who has already signed and it does not disturb the routing order.
  </Accordion>
  <Accordion title="Correct and resend">
    For when the document or the recipients were wrong. The original is voided with its trail intact and you rebuild it in the send flow with everything carried across, so you are not retyping the whole envelope. The voided original stays in the list for the record, and a banner across the rebuild says which envelope you are correcting.

    Field *values* are deliberately not carried: a value belongs to the signature that was collected on the old envelope, not to the new one.
  </Accordion>
  <Accordion title="Void envelope">
    Closes every signing link immediately. Signatures already collected stay on the record — voiding cancels the agreement, it does not erase what happened. A **reason** is required, and it goes into the audit trail beside the void.
  </Accordion>
</AccordionGroup>

<Tip>
  A signer can also decline, and a decline stops the envelope rather than skipping that person. Nobody further down the routing order is asked.
</Tip>

## What you get when it completes

Once the last party signs, Coverbase flattens every field into the page, seals the PDF, and generates a signing certificate beside it.

<Frame caption="An executed envelope. The status reads Executed, the document line names the seal level actually achieved, and Download signed copy becomes the primary action.">
  <img src="/images/user-guides/signing-envelope-executed.png" alt="Executed envelope detail with Download signed copy as the primary action, every field signed, and both parties green in the signing order" />
</Frame>

- **Download signed copy** — the sealed PDF, with every signature, initial and stamp burned into the page and attributed. It becomes the envelope's primary action once sealing finishes.
- **Download certificate** — the certificate of completion, under **Actions**. It only exists once every party has signed.
- **Download full packet** — the signed copy and the certificate together, for handing to a counterparty or an auditor.
- The document line under the file name reads **sealed at B-B** (or whatever level was achieved), so you can see at a glance what the executed copy actually carries rather than what was asked for.

The executed copy is also filed as a document on the associated vendor and contract, so it is where you would look for it even if you never open the envelope again.

## The audit trail

Every event is recorded in order and hash-chained: each entry carries a sequence number and a hash that covers the one before it. Removing or editing an entry breaks the chain, which is what makes the record worth something in a dispute.

<Frame caption="The audit trail. Each event carries who, when, from where, and a chain hash.">
  <img src="/images/user-guides/signing-audit-trail.png" alt="Audit trail showing envelope created, sent, signer notified, portal opened, consent accepted, signature adopted and signed events with IP addresses and hashes" />
</Frame>

Events cover the whole life of the envelope: created, sent, each party notified, each portal opened, consent accepted against a specific disclosure version, each signature adopted and applied, and the final seal. Portal events carry IP, approximate location and user agent.

The **Integrity** panel beside it is the part an auditor reads:

| | |
| --- | --- |
| **Source Document SHA-256** | The hash of the paper before anyone touched it. |
| **Executed Document SHA-256** | The hash of the sealed copy. Recorded once the envelope completes. |
| **Audit Chain Head** | The hash covering every event so far. |

<Tip>
  **Verify now** on the Overview tab re-checks the document you are holding against these hashes. That is the answer to "is this the file that was actually signed?"
</Tip>

## Common problems

<AccordionGroup>
  <Accordion title="A signer says the link does nothing">
    Check the envelope status first. A voided or expired envelope closes its links. If the envelope is live, check what the party has to get past before the document appears: **Authenticate signers' identity** emails them a one-time code, and an **Access code** on their recipient card asks for the code you were meant to hand them yourself. Either screen can be mistaken for a broken link.
  </Accordion>
  <Accordion title="Nobody after the first person has been emailed">
    That is routing working as designed. Later steps are notified as the envelope advances. If the first step has not finished, nobody after it has been asked.
  </Accordion>
  <Accordion title="The envelope sat at Preparing this document">
    Word files convert to PDF before they can be shown. The portal polls and resolves itself when the conversion lands, so a signer does not need to refresh.
  </Accordion>
  <Accordion title="The template will not let me edit it">
    An envelope has been sent from it, so the version is cited in an audit chain. Use **Edit as new version**; see [versioning](/user-guides/signature-templates#versioning-what-freezes-and-when).
  </Accordion>
</AccordionGroup>
